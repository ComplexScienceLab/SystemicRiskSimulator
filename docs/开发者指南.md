# SRS 开发者指南

## 1. 目标与定位

SystemicRiskSimulator（SRS）是一个配置驱动的实验编排器，核心定位是把“模型逻辑”和“实验运作流程”解耦：

- 模型逻辑放在 `Samples/libraries/models_library/*` 或其他外部模型目录。
- 实验运作流程由 `SystemicRiskSimulator/main.py` 和 `SystemicRiskSimulator/programs/experiments_program.py` 调度。
- 运行时会输出实验快照（config/agents/parameters/models）到实验输出目录，用于复现。

## 2. 核心执行链路

入口推荐：

```powershell
python -m SystemicRiskSimulator.main --global-config config.json --experiment ib2111
```

执行链路：

1. `main.py` 解析 CLI 参数并合成 `config`。
2. `simulator(config)` 读取 `set_config_variables.py`，合并为 `sgv`。
3. 创建实验目录并写入快照。
4. `programs/experiments_program.py` 根据运行方式调度（ABM/Gym/RL）。
5. `Operator.operate_installing()` 导入模型、参数、agents。
6. `Collector` 收集与导出实验数据。

## 3. “直接运行”与 data 目录策略

当前代码已支持开发优先的直接运行模式：

- `runtime_model_import_source='external'` 时，模型从 `folderpath_models` 直接导入。
- `runtime_copy_resources_into_simulator_data=False` 时，不再强制把 config/agents/parameters 复制到 `SystemicRiskSimulator/data/*` 作为正式运行源。

说明：

- 即使不作为运行源，`data/` 目录仍可作为模板或历史兼容目录存在。
- 输出目录中的快照机制仍保留，这是复现实验的关键资产。

## 4. Samples 的运作方式

`Samples/libraries` 下分四类资源：

- `configs_library/*/set_config_variables.py`：定义运行开关、路径、实验范围。
- `agents_library/*/set_agents_variables.py`：生成 `agents/*.pkl` 初始状态。
- `parameters_library/*/set_parameters_variables.py`：生成 `parameters.pkl` 任务组合。
- `models_library/*`：模型主体（`model_main.py`、`model_finance.py` 等）。

推荐准备顺序：

1. 先运行 `set_agents_variables.py` 生成 agents 数据。
2. 再运行 `set_parameters_variables.py` 生成 parameters 数据。
3. 最后用统一入口 `python -m SystemicRiskSimulator.main ...` 跑实验。

## 5. 模型家族说明

- `model_sample_IB1111`：传统单机制链式传染流程。
- `model_sample_IB1211`：在银行间机制外加入共同资产通道（DA/IBA）。
- `model_sample_IB2111`：引入 AB 行为层与策略、奖励、观测。
- `model_sample_IB2111_improved`：引入通用封装 `run_bank_interbank_cascade`。

## 6. 当前已知风险与排查建议

1. `model_sample_IB2111_improved` 依赖 `ComplexSystemLab` 提供的机制类。
2. 若无法导入 `CascadeFailuresModel_SingleMechanism`，请设置 `PYTHONPATH` 包含 `ComplexSystemLab` 根目录，或将其打包为可安装依赖。
3. 在当前参数下，improved 可能出现长时间不收敛（轮次和步进暴涨）。建议：
   - 降低 `test_max_num_of_turn` 做快速 fail-fast；
   - 缩小参数空间（先固定策略与冲击）；
   - 对比同一 `exp_id` 下 old/improved 的终态与轨迹。

## 7. 开发建议

1. 统一入口优先，逐步淘汰旧的 `from SystemicRiskSimulator.simulator import simulator` 风格。
2. 对每个 sample 提供“可一键准备 + 可一键运行”的脚本。
3. 对 improved 增加回归基线测试（终态破产集合、关键损失指标、收敛步数）。
4. 把 `ComplexSystemLab` 依赖显式化（可选 extras 或安装指引），避免隐式路径依赖。
