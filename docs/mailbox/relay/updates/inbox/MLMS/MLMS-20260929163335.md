# report-项目入口文件改判project类型-更新通告-20260929-001

> **性质声明**：本文是 **`report`** 文档（更新通告）。向正在运行的项目组会话通告「项目入口文件改判 `project` 类型」这一破坏性变更及其适配要求。
> 服务对象：**所有正在进行的项目组会话**（AI Agent 与人）。
> 本文不承担：变更的实施过程（→ `record`）· 执行的排期与待办（→ `task`）。

---

## 〇、给正在运行的会话的话（先读这段）

> **如果你正处在一个尚未完成的项目会话中，请先花 1 分钟读完本节。**

**发生了什么**：文档体系的类型闭集新增了 `project` 类型，且**所有项目入口文件（项目主页／项目总览）的文件名已被改名**。

**对你会话的直接影响**（三种，按常见度排序）：

| # | 症状 | 原因 | 怎么办 |
| --- | --- | --- | --- |
| 1 | 你之前记下的文件名 `notes-项目XXX-…md` **找不到了** | 已改名为 `project-项目XXX-…md` | 用新名，或用 `[[内容名]]` 短链（`aliases` 已含） |
| 2 | 你的 `[[双链]]` 指向旧名，**显示为未创建** | 旧名不复存在 | 把 `[[notes-项目XXX-…]]` 改为 `[[项目XXX]]` |
| 3 | 你在某项目目录下看到**新出现的空骨架** `project-项目XXX-20260929-001.md` | 该项目原本缺入口，本次新建 | **不要删**；若你在该项目工作，请顺手填充它 |

**最重要的三条纪律**：

1. **新写文档时**：项目入口用 `project-` 前缀；内部文档继续用原前缀（`notes-` / `design-` / `task-` …）。
2. **引用项目主页时**：优先写短链 `[[项目XXX]]`（`aliases` 已保证可解析），不要硬编码长文件名。
3. **发现失效引用**：按 §三 的规则改写，不要绕过（不要新建同名文件去"修好"链接）。

## 一、变更摘要

| 项 | 内容 |
| --- | --- |
| **变更类型** | ⚠️ **破坏性**（文件改名，引用会失效） |
| 生效时间 | 2026-09-29 |
| 影响范围 | 7 个 Obsidian Vault + MLMS 工程侧，共 **120** 个项目入口文件 |
| 是否可逆 | 可（有备份，见 §六） |
| 需要下游动作 | **是**（更新引用；详见 §三） |

### 1.1 核心变更：新增 `project` 类型

文档类型闭集由 **16** 个增至 **17** 个：

```text
新增：project  —— 项目入口 / 项目主页
```

| 项 | 内容 |
| --- | --- |
| **语义** | 一个项目的入口文件，导航该项目的设计、决策、任务与文档 |
| **族** | 资产族（跨越生命周期长期有效） |
| **强约束** | **一对一**（每项目恰一份）· **位置固定**（项目目录内）· **结构性必备** |
| **命名** | `project-项目<项目名>-YYYYMMDD-UID.md`（UID 常为 `001`） |
| **标签** | `类型/项目`（**沿用既有中文标签，未改**） |
| **必需章节** | 范围（简介）· 文档地图 · 工程仓库 · 子项目 · 状态摘要 · 维护规则 |
| **禁入章节** | 完整设计展开（→ `design`）· 任务细节（→ `task`）· 决策理由（→ `adr`） |

### 1.2 与 `index` 的边界（防混淆）

`index` 一词在体系内已承载多义（手写 `index-*`、插件生成 `_Index_of_*`、旧形制 `Index-of-*`、公开 `docs/README.md`），故项目入口**另立类型**：

> **`index` 的对象是「一堆文档」，回答「这些文档有哪些」；
> `project` 的对象是「一个组织实体」，回答「这个项目是什么、有哪些子项目、到哪了」。**

## 三、下游需要做什么（行动项）

### 3.1 必做：检查并更新引用

```text
① 搜索你项目笔记中的旧名引用
   搜：[[notes-项目
   搜：[[项目：          （带全角冒号的旧写法）
   搜：notes-项目

② 改写规则
   [[notes-项目场景工坊-20260714-001]]  →  [[项目场景工坊]]      ← 推荐短链
   或                                    →  [[project-项目场景工坊-20260714-001]]
   [[项目：YGE]]                        →  [[项目YGE]]
```

**为什么优先短链**：`project` 文件的 `aliases` 已含内容名，写 `[[项目场景工坊]]` 即可解析，且不受未来改名影响。

### 3.2 必做：新写文档时的类型选择

| 你要写的内容 | 用哪个前缀 |
| --- | --- |
| **项目入口 / 项目主页** | `project-项目<名>-<日期>-001` |
| 设计文档 | `design-` |
| 任务文档 | `task-` |
| 会议／讨论记录 | `record-` |
| 分析 | `analyse-` |
| 规范 | `spec-` |
| 其他笔记 | `notes-` |

**判定问句**：这份内容回答**这个项目是什么、有哪些子项目、到哪了**吗？
是 → `project`；否 → 按上表选。

### 3.3 建议：填充你所在项目的骨架

若你的项目目录下出现了新的空骨架 `project-项目XXX-20260929-001.md`，且你正在该项目工作，**建议顺手填充**：

| 章节 | 填什么 |
| --- | --- |
| 简介 | 项目是什么、边界在哪 |
| 文档地图 | 该项目主要设计／任务／文档的链接清单 |
| 工程仓库 | 本地与远程仓库地址 |
| 子项目 | 若为伞形项目 |
| 计划与进度 | 一句话基线 + 活跃任务的指针 |

> **注意**：状态摘要节**只放一句话 + 指针**，不展开计划内容——计划去 `plan-*`，进度去 `task-*`。

### 3.4 不要做

| ❌ 不要 | 原因 |
| --- | --- |
| 新建 `notes-项目XXX.md` 去"修复"失效链接 | 会制造重复文件，且违反新规范 |
| 在项目主页里写完整设计 | 那是 `design` 的职责（禁入章节） |
| 改回旧文件名 | 变更已生效，回退需走 §六 的备份流程 |
| 删除新出现的空骨架 | 那是项目结构的一部分 |

## 五、常见问题

| 问 | 答 |
| --- | --- |
| 项目入口为什么不用 `index`？ | `index` 已承载四义（手写索引／插件索引／旧形制／`docs/README`），再加会失去区分度 |
| 为什么标签还是 `类型/项目`（中文）？ | 类型轴标签用中文是**既有惯例**（`spec`↔`类型/规范`、`design`↔`类型/设计`），与英文前缀不要求字面一致 |
| 命名能不能放松（不加日期 UID）？ | **不能**。统一形制是自动化的前提——不统一会造成引用失效与校验困难 |
| UID 为什么总是 `001`？ | 项目入口一对一，天然无冲突，故恒为 `001` |
| 我项目没有入口文件怎么办？ | 检查是否已新建骨架；若无，按 §3.3 模板自行创建 |
