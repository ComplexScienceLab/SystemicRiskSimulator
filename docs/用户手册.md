# SRS 用户手册

## 一、这份手册解决什么问题

SystemicRiskSimulator，简称 SRS，是一个把系统性风险模拟实验拆成“统一调度器 + 四件套实验资源”的工具。你不需要每次都改主程序去适配新模型；你需要做的是准备好四件套，然后通过统一入口运行。

这份用户手册面向的是“使用者”，不是内核开发者。它重点回答以下问题：

1. SRS 到底怎么运行。
2. 四件套是什么，分别该怎么准备。
3. 常用程序有哪些，什么时候用哪个。
4. 配置文件该改哪里，哪些字段最重要。
5. 实验跑完以后结果在哪，出了问题先查什么。

如果你要修改主调度器或新增模型接口，请看开发者指南。如果你只是想运行 Samples，或把自己工程里的四件套挂到 SRS 上，本手册就是你的主要入口。

## 二、先建立一个正确的使用心智模型

SRS 的使用流程不是“打开某个模型文件直接运行”，而是下面这条链路：

1. 先准备四件套。
2. 再用 config 把四件套连接起来。
3. 再通过 main.py 统一运行。
4. 再由 SRS 自动执行实验、预处理、可视化等阶段。

四件套分别是：

1. config：告诉 SRS 去哪里找模型、参数和 agents，以及本次该跑哪些阶段。
2. agents：生成实验初始个体数据。
3. parameters：生成参数组合和实验任务表。
4. models：定义模型本体和状态推进逻辑。

记住一句话：

SRS 的正式输入不是“一个 Python 脚本”，而是一组按规范组织的四件套目录。

## 三、项目结构怎么看

仓库中你最常接触的目录有这些：

```text
SystemicRiskSimulator/
|- SystemicRiskSimulator/
|  |- main.py
|  |- programs/
|  |- core/
|  \- tools/
|- Samples/
|  |- exp/
|  \- libraries/
|- docs/
|- config.json
|- pyproject.toml
\- requirements.txt
```

每个位置的主要作用如下：

1. SystemicRiskSimulator/main.py：统一入口。平时运行实验主要用它。
2. SystemicRiskSimulator/programs：阶段程序，包括实验主程序、结果预处理程序、可视化程序。
3. Samples/exp：实验 JSON 样例。
4. Samples/libraries：SRS 自带的四件套样例。
5. docs：说明文档。
6. config.json：全局实验选择入口。

## 四、环境准备

### 4.1 Python 版本

当前项目建议使用 Python 3.11 及以上版本。若你与现有仓库环境保持一致，优先使用仓库已有 pyproject.toml 与 requirements.txt 所描述的依赖集合。

### 4.2 推荐安装方式

推荐优先使用 uv 创建环境并安装依赖：

```powershell
uv venv .venv
.\.venv\Scripts\Activate.ps1
uv pip install -r requirements.txt
```

如果你当前工作流仍在使用传统 venv，也可以这样做：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

无论哪种方式，建议在运行前确认：

1. 当前解释器来自本仓库虚拟环境。
2. SystemicRiskSimulator 包源码在当前解释器可导入。
3. pandas、numpy 等基础依赖已安装。

## 五、最常用的三种运行入口

SRS 当前提供三种最常用的实验选择方式。

### 5.1 方式一：通过 global config 选择实验

这是最推荐的日常用法。

```powershell
python -m SystemicRiskSimulator.main --global-config config.json --experiment ib2111
```

适用场景：

1. 你已经在 config.json 的 experiments 中登记好了实验。
2. 你希望以后反复运行同一个实验，只改 experiment 键名即可。
3. 你想把多个实验入口集中管理。

### 5.2 方式二：直接指定 experiment JSON

```powershell
python -m SystemicRiskSimulator.main --experiment-json Samples/exp/exp_sample_IB2111.json
```

适用场景：

1. 你想快速用一个单独 JSON 指向某个实验。
2. 你不想先改全局 config.json。

但要注意：experiment JSON 当前不是完全独立的纯配置系统。真正权威的实验细节仍然在 set_config_variables.py 中。实验 JSON 最可靠的用途，是提供 folderpath_config 以及少量真正契约一致的 override 字段。

### 5.3 方式三：直接指定 set_config_variables.py 所在目录

```powershell
python -m SystemicRiskSimulator.main --set-config-folder Samples/libraries/configs_library/config_sample_IB2111
```

适用场景：

1. 你已经明确知道要用哪个配置目录。
2. 你在调试单个实验，不想先改 config.json。

这是最接近“直接指定实验配置”的方式，也最适合快速验证四件套是否对齐。

## 六、四件套怎么用

### 6.1 config 怎么用

config 的正式文件是 set_config_variables.py。它定义的是这次实验的运行口径。

你在使用时最常需要检查的字段有：

1. folderpath_config。
2. folderpath_models。
3. folderpath_parameters。
4. folderpath_agents。
5. schedule_operation。
6. list_idsExperiment_to_run。
7. is_develope_mode。
8. runtime_model_import_source。

其中最重要的是四个路径字段，因为这四个字段决定了 SRS 去哪找正式资源。

如果路径错了，后面的所有步骤都不成立。

### 6.2 agents 怎么用

agents 不是你手工一个个改出来的文件，而是由 set_agents_variables.py 生成的一组 pkl。它们保存了实验初始个体状态。

使用步骤通常是：

1. 进入对应 agents 目录。
2. 运行 set_agents_variables.py。
3. 检查 agents 子目录是否生成了 pkl。
4. 检查 logfile.log 是否存在。

例如：

```powershell
Set-Location Samples/libraries/agents_library/agents_sample_IB2111
python set_agents_variables.py
```

运行后，你应该能在 agents 子目录里看到一组名字类似下面这样的文件：

```text
id=0-v=BB-year=2012-density_IB=1.00.pkl
id=0-v=IB-year=2012-density_IB=1.00.pkl
id=0-v=AB-year=2012-density_IB=1.00.pkl
id=0-v=note-year=2012-density_IB=1.00.pkl
```

这组文件是后续参数表和模型初始化要读取的正式输入。

### 6.3 parameters 怎么用

parameters 的正式产物是 parameters.pkl，推荐同时生成 parameters.xlsx 方便预览。

使用步骤通常是：

1. 进入对应 parameters 目录。
2. 运行 set_parameters_variables.py。
3. 检查 parameters.pkl 是否存在。
4. 必要时打开 parameters.xlsx 确认 exp_id 和关键参数列是否正确。

例如：

```powershell
Set-Location ../../parameters_library/parameters_sample_IB2111
python set_parameters_variables.py
```

参数表的核心作用是告诉 SRS：

1. 一共有多少个实验任务。
2. 每个实验任务对应哪组 agents。
3. 每个实验任务对应哪些冲击、策略、奖励参数。

### 6.4 models 怎么用

models 不需要你单独“执行生成”。它是被 SRS 直接 import 的代码目录。你要做的是：

1. 在 config 中把 folderpath_models 指向正确目录。
2. 确认模型目录结构完整。
3. 确认模型目录中的 __init__.py、model_main.py、model_finance.py、model_define.py 等文件存在。

SRS 当前默认直接从 folderpath_models 导入模型，并同时把这份模型代码快照复制到实验输出目录。

## 七、最常用的完整运行流程

下面给出一条最标准、最不容易出错的操作顺序。

### 步骤一：准备环境

```powershell
uv venv .venv
.\.venv\Scripts\Activate.ps1
uv pip install -r requirements.txt
```

### 步骤二：生成 agents

```powershell
Set-Location Samples/libraries/agents_library/agents_sample_IB2111
python set_agents_variables.py
```

### 步骤三：生成 parameters

```powershell
Set-Location ../../parameters_library/parameters_sample_IB2111
python set_parameters_variables.py
```

### 步骤四：回到仓库根目录

```powershell
Set-Location ../../../..
```

### 步骤五：运行实验

```powershell
python -m SystemicRiskSimulator.main --set-config-folder Samples/libraries/configs_library/config_sample_IB2111
```

如果你想从 config.json 里选实验，则使用：

```powershell
python -m SystemicRiskSimulator.main --global-config config.json --experiment ib2111
```

### 步骤六：检查输出

运行成功后，去 set_config_variables.py 中定义的输出根目录下看本次实验目录。通常会包含：

1. exp_output_data。
2. outputlog。
3. outputlog/config。
4. outputlog/agents。
5. outputlog/parameters。
6. outputlog/models。

如果这些快照目录不存在，说明本次运行没有完整走到 SRS 的正式主流程。

## 八、如何使用常用程序

### 8.1 experiments_program.py

这是实验主程序，负责真正运行参数任务、装载模型、推进状态和导出实验结果。

一般情况下，你不需要直接手动调用它。只需通过 main.py 运行，并在 set_config_variables.py 的 schedule_operation 中把“实验组模拟程序”设为 True。

### 8.2 transform_output_data_program.py

这是结果预处理程序。它适用于把实验输出转为更适合分析或可视化的格式，例如面板数据整理。

是否执行它，由 set_config_variables.py 中的这些配置决定：

1. schedule_operation 中“预处理实验结果程序”。
2. transform_data 中的具体子开关。

你通常不需要单独运行它，而是通过 main.py 让 SRS 在实验后自动串联执行。

### 8.3 visualize_data_program.py

这是可视化程序。它依赖前面已经生成或预处理好的结果数据，再根据可视化配置画图。

它常用来生成：

1. 资产负债表图。
2. 矩阵热图。
3. 网络图。
4. 拼版图。
5. 银行状态表。

是否执行它，取决于：

1. schedule_operation 中“可视化结果程序”。
2. visulization_process 中的细分开关。

### 8.4 开发模式与子进程模式

set_config_variables.py 中有一个很重要的字段：is_develope_mode。

1. True：开发调试模式。阶段程序在当前进程中 import 并执行，适合打断点。
2. False：常规模式。阶段程序通过子进程运行，更接近正式批量执行口径。

如果你是第一次调试模型，建议先把 is_develope_mode 设为 True。等模型稳定了，再切到 False 做更正式的运行测试。

## 九、常用配置项怎么理解

### 9.1 schedule_operation

这是阶段总开关。它决定这次运行是否执行：

1. 实验组模拟程序。
2. 预处理实验结果程序。
3. 可视化结果程序。
4. 分析实验结果程序。

如果你只想先确认模型主流程能不能跑通，可以先只开“实验组模拟程序”。

### 9.2 list_idsExperiment_to_run

这是最常用的调试字段之一。它决定本次跑哪些 exp_id。

常见用法：

1. None：跑全部实验。
2. [95]：只跑一条实验，便于调试。
3. 某个筛选列表：跑一个子集。

第一次排错时，强烈建议只跑 1 到 3 条实验，不要直接全量跑。

### 9.3 runtime_model_import_source

当前建议值是 external。它表示运行时直接从 folderpath_models 指向的模型目录导入代码。

另一种兼容值是 simulator_data，表示把模型复制到包内 data/model 后再从那里导入。除非你明确需要兼容旧路径，否则优先使用 external。

### 9.4 runtime_copy_resources_into_simulator_data

当前建议值是 False。它表示是否把 config、agents、parameters 等资源也复制到模拟器包内固定 data 目录。

大多数开发和正常使用场景下，不需要依赖这个旧式目录作为正式运行源。

## 十、config.json 怎么用

config.json 是“选择实验入口”的总开关，典型结构如下：

```json
{
  "runner": {
    "foldername_simulator": "SystemicRiskSimulator",
    "folderpath_realpath_simulator": "./../",
    "is_auto_confirmation": true
  },
  "experiments": {
    "ib2111": {
      "folderpath_config": "libraries/configs_library/config_demo"
    }
  }
}
```

其中：

1. runner 描述运行器的默认信息。
2. experiments 是实验集合。
3. 每个实验最关键的是 folderpath_config。

你可以把多个实验入口登记进 experiments，然后通过 --experiment 选择。

## 十一、如何在外部工程中使用 SRS

SRS 不要求所有四件套都放在 Samples 中。外部工程也可以接入，只要你满足基本目录契约。

推荐外部工程结构：

```text
外部工程根目录/
\- libraries/
   |- configs_library/
   |- agents_library/
   |- parameters_library/
   \- models_library/
```

然后你可以这样运行：

```powershell
python -m SystemicRiskSimulator.main --set-config-folder "D:/YourProject/libraries/configs_library/config_demo"
```

或把它登记到 config.json：

```json
{
  "experiments": {
    "demo": {
      "folderpath_config": "D:/YourProject/libraries/configs_library/config_demo"
    }
  }
}
```

外部工程接入时，要特别注意：

1. folderpath_config 指向的是配置目录，而不是单个文件。
2. 外部 set_config_variables.py 中的 folderpath_models、folderpath_parameters、folderpath_agents 最好写成相对外部工程根目录的路径。
3. 外部工程如果不是与 SRS 同级，runner 中与 simulator 路径有关的字段要按实际情况调整。

## 十二、输出目录怎么看

每次实验运行后，SRS 会创建一个实验目录。通常里面最重要的两块内容是：

1. exp_output_data：实验原始或处理中结果。
2. outputlog：日志和四件套快照。

outputlog 下最值得关注的是：

1. outputlog.txt：主日志。
2. config：本次实验实际使用的 set_config_variables.py 快照。
3. agents：本次实验实际使用的 agents 快照。
4. parameters：本次实验实际使用的 parameters 快照。
5. models：本次实验实际使用的 models 快照。

这几类快照是复现实验的核心资产。不要只盯着 exp_output_data，而忽略 input snapshot。

## 十三、最常见的问题与排查办法

### 13.1 找不到配置目录

表现：提示配置文件不存在，或 folderpath_config 无法解析。

先检查：

1. --set-config-folder 是否写到目录层。
2. config.json 中的 folderpath_config 是否拼对。
3. 该目录下是否真的存在 set_config_variables.py。

### 13.2 找不到 parameters.pkl

表现：Operator 在读取参数作业表时失败。

先检查：

1. 是否已经运行 set_parameters_variables.py。
2. folderpath_parameters 是否指向正确目录。
3. 是否生成了 parameters.pkl 或至少 parameters.xlsx。

### 13.3 找不到 agents 文件

表现：初始化实验时找不到某个 pkl。

先检查：

1. 是否已经运行 set_agents_variables.py。
2. parameters.pkl 中的 id_agents、year、density_IB 等列是否与文件名一致。
3. set_config_variables.py 中的 list_agents_data_filename_para_01 和 list_agents_data_filename_para_02 是否与你的文件命名规则一致。

### 13.4 模型导入失败

表现：ImportError、模块缺失、相对导入失败。

先检查：

1. folderpath_models 是否指向正确目录。
2. 模型目录里是否有 __init__.py。
3. model_main.py、model_finance.py、model_define.py 是否存在。
4. 如果模型内部用了相对导入，目录结构是否仍是完整包结构。

### 13.5 跑出来的不是你改过的模型

表现：你明明改了 models_library，但运行结果像旧版本。

先检查：

1. runtime_model_import_source 是否为 external。
2. config 中的 folderpath_models 是否真指向你修改的目录。
3. main.py 打印出的最终 config 是否和你想的一致。

### 13.6 跑得太慢或不收敛

先做这些缩减：

1. 把 list_idsExperiment_to_run 缩成一条。
2. 降低 test_max_num_of_turn。
3. 先关闭可视化和结果预处理，只保留实验主程序。
4. 缩小参数空间，优先做小样本验证。

## 十四、给新用户的最短建议

如果你第一次用 SRS，不要试图同时理解所有程序。请按下面最短路径做：

1. 用 Samples 的一套四件套，不要先接外部工程。
2. 先运行 set_agents_variables.py。
3. 再运行 set_parameters_variables.py。
4. 再用 --set-config-folder 跑 main.py。
5. 跑通后再回头理解 config.json、experiment JSON 和多实验管理。

只要你先把这条路径跑通，你就已经掌握了 SRS 的核心使用方式。
